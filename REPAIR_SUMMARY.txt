=== VERIFIED REPAIRS (5 categories) ===

1. ENVELOPE CONTRACT (sdks/python/sibna/envelope.py)
   - _canonical_payload(): Added sender_id as 4th field
     Canonical order: recipient_id || message_id || payload_hex || sender_id
     Each field prefixed with u64_be length encoding
     Matches Rust server: server/src/main.rs::send_message_handler and
     server/src/ws.rs::route_message
   - make_signed_envelope(): Signs canonical bytes directly with Ed25519
     Signs: identity.sign(canonical)  NOT: identity.sign(SHA_512(canonical))
   - verify_signed_envelope(): Verifies signature over canonical directly
     Verifies: vk.verify(signature, canonical)  NOT: vk.verify(signature, SHA_512(canonical))
   - Docstring: Documents the 4-field canonical form and fields NOT covered by signature

2. PREKEYBUNDLE X3DH IDENTITY-KEY DEFECT (sdks/python/sibna/x3dh.py)
   - prekey_bundle_from_bytes(): No longer returns x25519_identity_key=bytes(32)
     Now reads the key from the wire format data and raises ValidationError
     if the default bytes(32) placeholder is detected, since it would cause
     incorrect shared-secret derivation in DH computation (dh2 = DH(EK_A, IK_B.x25519))
   - generate_peer_bundle(): root_identity_key must be explicitly provided;
     raises ValidationError if None (removed ambiguous fallback to identity_ed.public_key)
   - signing_bytes(): Matches Rust PreKeyBundle::signing_bytes() wire format exactly

3. PYTHON HTTP AUTHENTICATION (sdks/python/sibna/client.py)

   - send_message(): Added Authorization: Bearer <jwt> header
   - fetch_inbox(): Added Authorization: Bearer <jwt> header;
     identity_key_hex passed as query param (required by Rust inbox_handler
     for identity binding check: claims.sub != q.identity_key_hex)
   - Removed 'token' from query params in fetch_inbox()
